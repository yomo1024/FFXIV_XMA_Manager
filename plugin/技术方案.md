# FFXIV Mod 一键安装：网页 ↔ Dalamud 插件 ↔ Penumbra 技术方案

> 目标：用户在网页上点「安装」，网页把 mod 信息发给游戏内的 Dalamud 插件，插件把 mod 装进 Penumbra，并让它在游戏里立刻生效。
>
> 本文所有 API 签名与行为**都来自真实源码/官方包**（不是推测），来源见文末「证据来源」。

---

## 0. 先纠正三个前提（这三点会直接改变设计）

| 直觉 | 实际情况 | 影响 |
|---|---|---|
| 「Penumbra 的 IPC 是一堆字符串名，要去查签名」 | Penumbra 官方发布了**类型化 API 包 `Penumbra.Api`（NuGet，当前 5.19.2，目标框架 net10.0-windows）**，直接 `new IpcSubscribers.InstallMod(pi).Invoke(path)` 即可，**不用手写字符串** | 开发量大幅下降，且有编译期类型检查 |
| 「网页直接跟插件/游戏通信」 | ① 浏览器**不允许**普通公网网页随意读写 `127.0.0.1`（CORS + Private Network Access 预检）② Penumbra **自己就有一个 HTTP API**，但它的 CORS 只对自己那个源开放，且需要手动开启 | 需要**自研插件做中转**（你的方案是对的），插件负责补 CORS/PNA 头 + 鉴权 |
| 「自己解压 mod 包写进 Penumbra 目录」 | Penumbra 有 `InstallMod(pmp路径)`，**它自己解包并放进 mod 根目录**（源码：`_modImportManager.AddUnpack(path)` → TexToolsImporter → `modManager.AddMod(dir)`） | 首选「丢给 Penumbra 装」；自己写目录只在有特殊需求时才做 |

另外：Penumbra 的源码仓库是 **`xivdev/Penumbra`**（活跃，默认分支 `testing`）。
`Ottermandias/Penumbra` 那个仓库**停在 2021 年的 0.2.0.1**，别参考它。

## 1. 总体架构

```
┌─────────────┐   HTTPS/HTTP   ┌──────────────────────────────┐
│  你的网站    │ ─────────────► │  Dalamud 插件（跑在游戏进程内）│
│  （浏览器）  │  POST /install │  ① 本地 HTTP 服务(127.0.0.1)  │
│             │ ◄───────────── │  ② 下载队列 + 进度            │
└─────────────┘   JSON 回执     │  ③ 调 Penumbra IPC            │
                               └───────────────┬──────────────┘
                                               │ IDalamudPluginInterface IPC
                                               ▼
                               ┌──────────────────────────────┐
                               │  Penumbra 插件                │
                               │  ~/.config 里的 mod 根目录     │
                               └──────────────────────────────┘
```

为什么必须要有插件（而不是网页直连 Penumbra 的 HTTP API）：

1. Penumbra 的 HTTP API（`http://localhost:42069/api/...`）**要在 Advanced 配置里手动开** `EnableHttpApi`，默认不一定开；
2. 它的 CORS 是 `WithCors("http://localhost:42069/")`，**只允许它自己那个源**，你的网站源拿不到响应；
3. 浏览器对「公网页面 → 本地地址」会做 **Private Network Access 预检**，Penumbra 不会回 `Access-Control-Allow-Private-Network`，请求会被拦；
4. 就算能通，也没有鉴权——任何网页都能往你机器装 mod。

而自研插件可以：自己加 CORS/PNA 头 ✓、做 token 鉴权 ✓、管下载和进度 ✓、在游戏里弹 ImGui 界面 ✓、并且能调用**完整的 IPC API**（启用/优先级/集合/重绘）✓。

## 2. Q1：在 Dalamud 插件里调用 Penumbra（IPC / CallGate）

### 2.1 正确做法：用 `Penumbra.Api` NuGet 包（推荐）

```xml
<ItemGroup>
  <PackageReference Include="Penumbra.Api" Version="5.19.*" />
</ItemGroup>
```

`IpcSubscribers` 是**类型化订阅器**：`new Xxx(pluginInterface)` 得到对象，用 `.Invoke(...)` 调用；
每个类还有 `Label` / `LabelU8` 静态字段，就是它背后真正的 IPC 字符串（例如 `Penumbra.InstallMod`），调试时可以打日志。

### 2.2 你会用到的签名（已从官方包 XML 文档核对）

**装 mod / 管 mod（`IPenumbraApiMods`）**

| 调用 | 签名 | 官方说明 / 行为 |
|---|---|---|
| `InstallMod` | `PenumbraApiEc InstallMod(string modFilePackagePath)` | 「像手动安装一样解包并安装 `.pmp / .pcp / .ttmp / .ttmp2`」。**Success 只代表成功入队，不代表装好了**。文件不存在返回 `FileMissing` |
| `AddMod` | `PenumbraApiEc AddMod(string modDirectory)` | 把**已在 mod 根目录下**的文件夹登记为 mod（参数是目录名，不是完整路径；路径跑到根目录外会 `InvalidArgument`） |
| `ReloadMod` | `PenumbraApiEc ReloadMod(string modDirectory, string modName)` | 「等同于按一下重载按钮，**如果 mod 已失效可能会被删掉**」；找不到返回 `ModMissing` |
| `DeleteMod` | `PenumbraApiEc DeleteMod(string modDirectory, string modName)` | |
| `GetModList` | `Dictionary<string,string> GetModList()` | key=目录名，value=mod 名 |
| `GetModPath` | `(string, bool, bool) GetModPath(string modDirectory, string modName)` | |
| `SetModPath` | `PenumbraApiEc SetModPath(...)` | 改目录名 |

**插件状态（`IPenumbraApiPluginState`）**

| 调用 | 签名 | 说明 |
|---|---|---|
| `GetModDirectory` | `string GetModDirectory()` | **Penumbra 的 mod 根目录完整路径**（要这个，别硬编码 `%APPDATA%`） |
| `GetConfiguration` | `Dictionary<string, object?> GetConfiguration()` | |

**启用 / 优先级 / 设置（`IPenumbraApiModSettings`）**

| 调用 | 签名 |
|---|---|
| `TrySetMod` | `PenumbraApiEc TrySetMod(Guid collectionId, string modDirectory, string modName, bool enabled)` |
| `TrySetModPriority` | `PenumbraApiEc TrySetModPriority(Guid collectionId, string modDirectory, string modName, int priority)` |
| `TrySetModSettings` | `PenumbraApiEc TrySetModSettings(Guid, string, string, IReadOnlyList<string> group, string)` |
| 取集合 Id | `GetCollection(ApiCollectionType.Current)` → `.Id`（当前角色实际生效的集合） |

**UI / 重绘**

| 调用 | 签名 |
|---|---|
| `OpenMainWindow` | `PenumbraApiEc OpenMainWindow(TabType tab, string modDir, string modName)` |
| `RedrawAll` | `void RedrawAll(RedrawType type)` → 让改动**立刻在游戏里可见** |
| `RedrawObject` | `void RedrawObject(int objectTableIndex, RedrawType type)` |

**事件（订阅式，用于「装好了通知我」）**

```csharp
ModAdded.Subscriber(pi,  Action<string> modDir)
ModDeleted.Subscriber(pi, Action<string>)
ModMoved.Subscriber(pi,  Action<string,string>)
ModDirectoryChanged.Subscriber(pi, Action<string,bool>)
Initialized.Subscriber(pi, Action)      // Penumbra 后加载时重连
Disposed.Subscriber(pi, Action)
```

**兼容性检查（务必做）**

```csharp
var (major, minor) = new Penumbra.Api.IpcSubscribers.ApiVersion(pi).Invoke();
if (major < 5) { /* 提示用户升级 Penumbra */ }
```

> Penumbra ≥ 某版本开始用新的 `Luna.CallerPlugin` 适配层提供 `IPenumbraApi`（`GetModManagerAdapter(...)` 等）。
> 上面的 `IpcSubscribers.*` 仍然可用（开源插件 ModArchiveBrowser 就是这么用的），**先用它们，够用**。

### 2.3 「Provider/Subscriber 模式」的正确理解

- **Provide**：插件暴露能力 → `pi.GetIpcProvider<T>(name)`（Penumbra 用它把函数注册出去）。
- **Subscribe/Call**：插件消费能力 → `pi.GetIpcSubscriber<T>(name)`，对应 `Penumbra.Api` 里 `IpcSubscribers.Xxx` 的 `Invoke`。
- 用 `Penumbra.Api` 就不用直接碰这两个（它内部已经包好了）。
- 但**"是否可以调用"要显式判断**：拿不到 provider 时 `Invoke()` 会抛异常。稳妥写法：

```csharp
private readonly InstallMod _installMod;
public PenumbraBridge(IDalamudPluginInterface pi) { _installMod = new InstallMod(pi); }

public bool Ready { get; private set; }
public void Refresh()   // 每次要调之前刷新一下，Penumbra 可能刚加载完
{
    try { var (ma,mi) = new ApiVersion(pi).Invoke(); Ready = ma >= 5; }
    catch { Ready = false; }
}
```

## 3. Q2：插件里的本地 HTTP 服务（接收网页指令）

### 3.1 用什么实现

| 方案 | 结论 |
|---|---|
| `System.Net.HttpListener` | ❌ 不推荐：绑定非 `localhost` 前缀需要 **URL ACL + 管理员权限**，Dalamud 插件跑在游戏进程里，弹 UAC 不可接受 |
| **Kestrel**（`Microsoft.AspNetCore.App`，`WebApplication.CreateBuilder` / `KestrelServer`） | ✅ 推荐：纯托管 socket，**不需要 ACL/管理员**；自带路由、JSON、CORS 中间件 |
| 裸 `TcpListener` + 手写最小 HTTP | ✅ 可行（不想加 ASP.NET 依赖时），约 100 行；功能自控 |

不需要额外包时也可以直接用 `HttpListener` 的替代品，但建议直接上 Kestrel。

### 3.2 必备的四件事

```csharp
var builder = WebApplication.CreateBuilder();
builder.WebHost.ConfigureKestrel(k => k.Listen(IPAddress.Loopback, port));  // 只监听 127.0.0.1
builder.Services.AddCors(o => o.AddDefaultPolicy(p => p
    .SetIsOriginAllowed(_ => true)          // 你的网站源（或精确白名单）
    .AllowAnyHeader().AllowAnyMethod()
    .WithExposedHeaders("*")));
var app = builder.Build();
app.UseCors();

// ① 私有网络访问（Chrome 对"公网页面 → 127.0.0.1"会先发预检）
app.Use(async (ctx, next) =>
{
    if (ctx.Request.Method == "OPTIONS")
        ctx.Response.Headers["Access-Control-Allow-Private-Network"] = "true";
    await next();
});

// ② 简易鉴权：token 放在 X-ModBridge-Token 头
app.Use(async (ctx, next) =>
{
    if (ctx.Request.Headers["X-ModBridge-Token"] != Token) { ctx.Response.StatusCode = 403; return; }
    await next();
});

app.MapGet("/ping",  () => Results.Json(new { ok = true, ver = BuildInfo, penumbra = _bridge.Ready }));
app.MapPost("/install", async (InstallRequest req, CancellationToken ct) => { ... });
app.MapGet("/status", (string jobId) => ...);
app.Listen();      // 注意线程模型（见 3.3）
```

**Token 从哪来**：插件启动时生成随机串，显示在游戏内 `/xhud`（或插件主窗口）里并提供「复制」，用户在网页上粘贴一次记住（存 localStorage）。比"任何网页都能装 mod"安全得多。

### 3.3 线程模型（关键，容易踩）

浏览器请求落在 **线程池线程** 上；而 Dalamud/Penumbra 的 IPC 与游戏中对象**最好在 framework 线程上碰**。
Penumbra 自己的 HTTP 服务就是这么干的（源码 `HttpApi.cs`）：

```csharp
await framework.RunOnFrameworkThread(() => api.Redraw.RedrawAll(RedrawType.Redraw));
```

插件侧同理：

```csharp
_framework.RunOnFrameworkThread(() => _bridge.InstallMod(downloadedPmpPath));
```

建议把「下载」放后台线程/异步（耗时、可取消），把「调 IPC / 改状态 / 碰 ImGui」都丢回 framework 线程；用一个任务队列 + 进度字段（`volatile` / lock）给 `/status` 读。

### 3.4 建议的 HTTP 接口（对你现有网页端最自然）

```
GET  /ping                     → {ok, ver, penumbraReady, modDir}
POST /install                  → body: {url|modId, name, author, targetDirName?, enable?}
                                 → {jobId}
GET  /status?jobId=xxx         → {state: queued|downloading|installing|done|error,
                                  pct, downloaded, total, modDirName, modName, error}
POST /enable {modDir, modName, enabled}     → TrySetMod
POST /priority {modDir, modName, priority}  → TrySetModPriority
GET  /mods                     → GetModList()
POST /redraw                   → RedrawAll(Redraw)
POST /reveal {modDir, modName} → OpenMainWindow(TabType.Mods, ...)  // 游戏里高亮这条
```

下载大文件要**流式 + 进度**（mod 常有几十~几百 MB），并支持取消。

## 4. Q3：把 mod 正确写进 Penumbra 的 mod 目录

### 4.1 路线 A（推荐）：丢给 Penumbra 自己装

```csharp
string modRoot = _bridge.GetModDirectory();            // 例：C:\Users\x\AppData\Roaming\XIVLauncher\pluginConfigs\Penumbra\Mods
string tmp     = Path.Combine(_pluginConfigDir, "downloads", $"{Guid.NewGuid():N}.pmp");
await DownloadAsync(url, tmp, progress, ct);           // 流式下载
var ec = _framework.RunOnFrameworkThreadFunc(() => _bridge.InstallMod(tmp));
// ec == PenumbraApiEc.Success 只表示"已入队"，真正装完要等 ModAdded 事件或轮询 GetModList()
```

**为什么这是首选**：`InstallMod` 内部就是 `_modImportManager.AddUnpack(path)`
→ TexToolsImporter 解包 → `modManager.AddMod(dir, true)` 登记并加载。
也就是说 **Penumbra 会自己决定目录名、自己写 meta、自己登记、自己加载**，
你不用管 mod.json 的字段格式（这是最容易做错、最容易随版本失效的部分）。

**判断"装好了"**：订阅 `ModAdded.Subscriber(pi, dir => ...)`；
或安装前后对比 `GetModList()` 的差集（更简单、无状态）。

**已知坑**：
- `ModImportManager.AddUnpack` 对**同一路径 5 秒内重复提交会去重**（源码里有 `_uniqueModsToUnpack` 时间戳判断）→ 别对同一个临时文件连点两次；同一个包重装请**换个临时文件名**或间隔 > 5s。
- 临时 .pmp 下载完成后**别立刻删**：解包是异步队列，删早了会 `FileMissing`。建议装完（`ModAdded` / 轮询确认）再删，或让临时文件保留到插件卸载时清理。

### 4.2 路线 B：自己写目录，再 `AddMod`

只有当你需要自定义目录名/预置分组时才用。目录结构（**Penumbra v4 布局，已从 `FilenameService.cs` 核对**）：

```
<modRoot>\<你的mod目录名>\
    meta.json                                  ← 元数据（ModMeta，CurrentFileVersion = 4）
    default_mod.json                           ← 默认选项包含的文件映射
    group_001_<分组名>.json                    ← 可选的组/选项（group_*.json）
    <实际文件>…                                ← 例如 .tex/.mdl/.mtrl 等，或 mod 作者给的原始文件
```

- 三个 json 的角色：`meta.json`（名称/作者/描述/版本/优先级/标签…）、`default_mod.json`（默认选项 → 游戏路径映射）、`group_*.json`（分组与可选选项）。
- 写完目录后调用：

```csharp
_bridge.AddMod("<你的mod目录名>");     // 只传目录名！它内部会 join(modRoot, 名字)，父目录必须是 modRoot
```

- **`meta.json` 的字段格式没有公开稳定契约**，跟着 Penumbra 版本变（当前 `CurrentFileVersion = 4`）。
  → 所以**强烈建议路线 A**；如果必须走 B，最稳的是让用户在 Penumbra 里导出一次模板、或从现有 mod 复制结构。

### 4.3 装完之后

```csharp
// 1) 让它生效（可选，InstallMod 后 Penumbra 一般已加载；手动写目录后建议 reload）
_bridge.ReloadMod(modDirName, modName);      // 注意：mod 失效时可能被删除

// 2) 在集合里启用 + 设优先级
var col = _bridge.GetCurrentCollectionId();  // GetCollection(ApiCollectionType.Current)!.Value.Id
_bridge.TrySetMod(col, modDirName, modName, true);
_bridge.TrySetModPriority(col, modDirName, modName, 0);

// 3) 立刻可见
_bridge.RedrawAll(RedrawType.Redraw);
```

## 5. Q4：触发 Penumbra 重载

| 目的 | 调用 |
|---|---|
| 重载某条 mod（= 界面上的「重载」按钮） | `ReloadMod(modDir, modName)` |
| 重载后让模型/贴图立刻刷新 | `RedrawAll(RedrawType.Redraw)`；只刷某个对象 `RedrawObject(idx, RedrawType.Redraw)` |
| 目录名要改 | `SetModPath` |
| 新建的空 mod 目录 | `AddMod(目录名)`（若配合 `AddModBefore/After` 之类顺序需求，用 `TrySetModPriority` 调优先级） |

> `ReloadMod` 的关键语义：**"可能删掉已经失效的 mod"**。所以千万别在"文件还没写完"时调它；
> 也不要用它当"刷新列表"的手段。装完后更推荐 `RedrawAll`。

## 6. 端到端时序（一键安装）

```
网页                     插件(HTTP)                 线程                      Penumbra
 │  POST /install           │                        │                            │
 │─────────────────────────►│ 校验 token/参数         │                            │
 │  201 {jobId}             │ 建任务(queued)          │                            │
 │◄─────────────────────────│                        │                            │
 │                          │ 后台线程：流式下载 .pmp  │                            │
 │  GET /status?jobId=…     │ → {downloading, 42%}   │                            │
 │─────────────────────────►│                        │                            │
 │                          │ 下载完                 │                            │
 │                          │ ─────────RunOnFrameworkThread────────► InstallMod(pmp)
 │                          │                        │                            │ 解包+登记+加载
 │                          │                        │ ◄─── ModAdded(dir) ────────│
 │  GET /status             │ → {done, modDir, name} │                            │
 │─────────────────────────►│                        │                            │
 │                          │ 启用/优先级 (TrySetMod / TrySetModPriority)          │
 │                          │ RedrawAll(Redraw)      │                            │
```

网页端 SDK 草案：

```js
const H = 'http://127.0.0.1:42100';
const T = localStorage.getItem('modbridge_token');
async function install(info) {
  const r = await fetch(H + '/install', { method: 'POST',
      headers: { 'Content-Type': 'application/json', 'X-ModBridge-Token': T },
      body: JSON.stringify(info) });
  const { jobId } = await r.json();
  for (;;) {
    const s = await (await fetch(`${H}/status?jobId=${jobId}`,
        { headers: { 'X-ModBridge-Token': T } })).json();
    updateUI(s);
    if (s.state === 'done' || s.state === 'error') return s;
    await new Promise(r => setTimeout(r, 500));
  }
}
```

## 7. 容易踩的坑（清单）

1. **`HttpListener` 要管理员** → 用 Kestrel / TcpListener。
2. **只允许监听 `127.0.0.1`**；`0.0.0.0` 等于把机器开放给局域网。
3. **必须鉴权**（token），否则任意网页可 CSRF 式地 POST 到你本地端口装 mod。
4. **CORS + `Access-Control-Allow-Private-Network`**：https 网页 → `http://127.0.0.1` 会触发 PNA 预检（Chrome）；Safari/Firefox 行为不同，需要实测。
5. **线程**：HTTP 线程不要直接碰游戏对象/ImGui；用 `RunOnFrameworkThread`。
6. **`InstallMod` 返回 Success ≠ 装好**（只入队）→ 用 `ModAdded` 或列表差集确认。
7. **同一路径 5 秒内重复安装会被吞**（去重逻辑）。
8. **临时 .pmp 不要急着删**（异步解包）。
9. **`ReloadMod` 会删掉失效 mod**，别乱调。
10. **mod 目录名会被规范化**（`ReplaceNonAsciiOnImport` 配置项：非 ASCII 字符可能被替换）→ 你传入的名字和最终目录名可能不同，**用 `GetModList()` 的实际结果**。
11. **文件/路径长度**：Windows 260 字符限制 + mod 名很长时容易炸，尽量用短临时路径。
12. **Penumbra 后加载**：插件启动时 Penumbra 可能还没就绪 → 用 `Initialized.Subscriber` 重连，并在每次调用前判断 `Ready`。
13. **网络**：mod 站可能挡外链（403/Cloudflare），下载器要能带 `Referer`/`User-Agent`，必要时借游戏内 HTTP 或提示用户手动下载。
14. **端口冲突**：固定端口 + 冲突时回退，并把最终端口告知网页（写在 UI 里让用户复制；或用固定端口 + 明确的错误提示）。
15. **游戏内更新**：改完 mod 后需要 `RedrawAll`，否则要等换地图/重开窗口。

## 8. 项目骨架

```
ModBridge/
  ModBridge.csproj                  # <Project Sdk="Dalamud.NET.Sdk/15.0.0">（当前模板的 SDK 版本）
  ModBridge.json                    # 插件清单（Author/Name/Punchline/Description/RepoUrl/Tags + DalamudApiLevel）
  Plugin.cs                         # IDalamudPlugin：接线、生命周期
  Configuration.cs                  # IPluginConfiguration：端口、token、下载源
  PenumbraBridge.cs                 # 封 Penumbra.Api 的 IpcSubscribers（见下）
  Http/ LocalServer.cs              # Kestrel：/ping /install /status /mods /enable /redraw
  Http/ Jobs.cs                     # 任务队列 + 进度 + 取消
```

`PenumbraBridge.cs` 最小可用版：

```csharp
using Dalamud.Plugin;
using Penumbra.Api.Enums;
using Penumbra.Api.IpcSubscribers;

public sealed class PenumbraBridge(IDalamudPluginInterface pi, IPluginLog log)
{
    private readonly GetModDirectory  _modDir    = new(pi);
    private readonly GetModList       _modList   = new(pi);
    private readonly InstallMod       _install   = new(pi);
    private readonly AddMod           _addMod    = new(pi);
    private readonly ReloadMod        _reload    = new(pi);
    private readonly DeleteMod        _delete    = new(pi);
    private readonly ApiVersion       _version   = new(pi);
    private readonly GetCollection    _collection= new(pi);
    private readonly TrySetMod        _setMod    = new(pi);
    private readonly TrySetModPriority _setPrio  = new(pi);
    private readonly RedrawAll        _redraw    = new(pi);

    public bool Available { get; private set; }
    public string ModDirectory { get; private set; } = "";

    public void Refresh()
    {
        try
        {
            var (ma, mi) = _version.Invoke();
            Available    = ma >= 5;
            ModDirectory = Available ? _modDir.Invoke() : "";
            log.Information($"Penumbra API {ma}.{mi}, mods at {ModDirectory}");
        }
        catch (Exception e) { Available = false; log.Warning(e, "Penumbra 不可用"); }
    }

    public Dictionary<string,string> Mods()          => Available ? _modList.Invoke() : [];
    public PenumbraApiEc Install(string pmpPath)     => _install.Invoke(pmpPath);
    public PenumbraApiEc Add(string dirName)         => _addMod.Invoke(dirName);
    public PenumbraApiEc Reload(string dir,string n) => _reload.Invoke(dir, n);
    public PenumbraApiEc Delete(string dir,string n) => _delete.Invoke(dir, n);
    public Guid CurrentCollection()
        => _collection.Invoke(ApiCollectionType.Current)?.Id ?? Guid.Empty;
    public PenumbraApiEc SetEnabled(Guid c,string d,string n,bool on) => _setMod.Invoke(c,d,n,on);
    public PenumbraApiEc SetPriority(Guid c,string d,string n,int p)  => _setPrio.Invoke(c,d,n,p);
    public void Redraw() => _redraw.Invoke(RedrawType.Redraw);
}
```

> `Penumbra.Api.Enums.PenumbraApiEc` 的取值：`Success / FileMissing / ModMissing / CollectionMissing / InvalidArgument / NothingChanged / NothingDone ...`
> 建议把返回值原样回传给网页，便于前端给出准确提示。

## 10. 待你在自己机器上确认的点

1. **Penumbra 是否启用 HTTP API**（`advanced.json` → `EnableHttpApi`）：如果开了，插件里也可以把它当兜底通道（`POST http://localhost:42069/api/installmod` + `{"Path": "..."}`）——但正常走 IPC 更好。
2. **你的网站是 http 还是 https**：https 下浏览器对 `127.0.0.1` 的 PNA 预检更严格，需要实测 Chrome/Edge。
3. **mod 来源**：xivmodarchive 的下载直链是否需要 cookie/Referer（我之前给你的那个工具里已经处理过 403/Cloudflare 的情况，可复用思路）。
4. **是否要账号体系**：如果网页是公开的，建议「网页生成一次性 code → 用户在游戏内确认」的双向绑定，而不是让网页随便调本地端口。
5. **端口**：`42069` 是 Penumbra 的；你插件选一个不冲突的（示例用 `42100`），并处理占用回退。

### 12.3 实现里的关键取舍

- **`PenumbraBridge` 内部统一 `RunOnFrameworkThread`**：HTTP 线程可以直接调桥接方法，不用每个调用点自己管线程（与 Penumbra 自己的 HTTP 层同一套路）。
- **等"装好了"用三条路兜底**：`ModAdded` 事件给的目录名 → `GetModList()` 前后差集 → mod 根目录 mtime 最新且 5 分钟内（防 Penumbra 覆盖同名目录导致差集为空）。因为 `InstallMod` 既不入队回执也不返回目录名。
- **每个任务用新的临时文件名**（`HHmmss_<jobid>.pmp`）：绕开 Penumbra「同一路径 5 秒内重复提交被去重」。
- **失败也要说人话**：`PenumbraApiEc` 原样回传网页，`/status` 里带 `steps[]`（每步一行，界面上悬停可见）。
- **鉴权 + 域名白名单**：`/ping` 免 token（只暴露"插件在不在"，不含 token/mod 内容），其余接口必须带 token；默认允许任意下载域名，可切成白名单模式。
