# FFXIV Mod 工具包 v1.0

一个压缩包，三样东西，各用各的、配合起来用：

| 文件夹 | 是什么 | 装在哪 |
|---|---|---|
| `1-Manager-管理器` | **ModManager**（Web 管理器）：扫目录 / 入库 / 编辑 / 生成 Excel 汇总表 / 分类管理（含在线改名·删除）/ 下载工作台 | 任意位置双击即用（绿色版） |
| `2-ModBridge-游戏插件` | **ModBridge**（Dalamud 游戏内插件）：管理器里点「安装到游戏」→ 游戏内确认 → 装进 Penumbra 并即时生效（带预览图） | 游戏侧（一次性部署） |
| 迁机指南 | **docs/迁移到新电脑.md**：换电脑时怎么把库 + 配置一起搬过去 | — |
| `3-BrowserExt-浏览器拓展` | **浏览器拓展**：在 XIVModArchive 的 Mod 页面右下角一键「下载并导入管理器」 | 你自己的浏览器（一次性加载） |

**核心思路**：浏览器负责**下载**（用你已登录的身份），管理器负责**接住并入库**（写 地址.txt / 自动编号 / 抓封面 / 重扫 / 导 Excel），游戏插件负责**把 Mod 装进游戏**。全程只有一个浏览器，不用再登一次。

## 一、装（一次性）

### 1. 管理器（必须，最简单）
把 `1-Manager-管理器` 整个文件夹放到你喜欢的位置（例如 `G:\Games\FFXIV\Soft`），双击里面的 **`启动Web版.bat`**，
浏览器打开 `http://127.0.0.1:8765` 即可。第一次进「设置」把 **Mod 根目录 / 汇总表 Excel** 指好。

### 2. 浏览器拓展（强烈建议）
1. 地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`）
2. 右上角打开 **开发者模式**
3. 点 **「加载已解压的扩展程序」** → 选 `3-BrowserExt-浏览器拓展` 这个文件夹
4. 扩展列表里点「固定」，工具栏就有图标了

### 3. 游戏插件 ModBridge（想要"点一下就装进游戏"就装）

**最省事的办法：用 Dalamud 自定义插件源（可自动更新）**

1. 游戏内 `/xlsettings` → **Experimental** → **Custom Plugin Repositories**
2. 粘下面任意一条，点 `+` 添加（**国内一般选第二条更稳**）：
   ```
   https://raw.githubusercontent.com/yomo1024/FFXIV_XMA_Manager/main/pluginmaster.json
   https://cdn.jsdelivr.net/gh/yomo1024/FFXIV_XMA_Manager@main/pluginmaster-cdn.json
   ```
3. 保存 → `/xlplugins` → 找到 **Mod Bridge** → 安装 → 启用
4. 以后插件有更新会自动出现在更新列表里
   > **拿不到新版本**：源地址优先用 **raw** 那条（缓存几分钟）；用 jsDelivr 时它会缓存分支内容几小时，
   > 清缓存两招 —— ① 访问 `https://purge.jsdelivr.net/gh/yomo1024/FFXIV_XMA_Manager@main/pluginmaster.json`
   > 返回 JSON 即清成功（`pluginmaster-cdn.json` 同理）；② 地址末尾加 `?v=20260924` 换个 query 立刻拿新版。

**插件窗口（游戏内 `/modbridge`）能调的东西**：装完自动启用 ｜ 收到请求自动弹窗 ｜ **安装完成后自动关闭窗口** ｜
允许任意下载域名 ｜ 装完删临时文件 ｜ 启动时自动开 HTTP ｜ 封面自绘 / 封面高度比例 ｜ Heliosphere 规范目录名 /
交给 Heliosphere 插件画 ｜ 安装记录保留条数 ｜ 下载 Referer。

### 搬到新电脑（迁机）

备份包里带了**配置**（云盘 Cookie / 分类顺序 / 界面偏好 / 各类目录）。在新电脑上：
装部署包 → 「备份 / 恢复」恢复备份时勾 **套用备份里的配置** → 路径类项（Mod 根目录 / 汇总表 /
下载 / 暂存 / Penumbra / 备份目录）如果新电脑上不存在会**自动保留新电脑当前设置**（差异会列出），
然后插件那边点一次「测试连接 / 自动配对」就完事。详细步骤见 `docs/迁移到新电脑.md`。

**或者手动部署**（不想加插件包源时）：
先**关掉游戏**，然后：
- 推荐：运行 `2-ModBridge-游戏插件\setup.bat`（自动找 XIVLauncherCN / XIVLauncher，把插件放进 devPlugins）
- 或者：看 `2-ModBridge-游戏插件\手动部署-游戏插件.md` 手动放（那个文档里有 12 个文件的清单和常见坑）

装完启动游戏 → `/xlplugins` → Dev Plugins → 启用 **Mod Bridge** → `/modbridge` 能看到端口和 token 就成了。
（如果插件列表里没有：游戏内 `/xlsettings` → Experimental → **Dev Plugin Locations** 把这个文件夹加进去 → 重启游戏）

## 二、日常怎么用（两条路，选你顺手的）

### 路线 A：浏览器拓展（推荐，最省事）
1. 在**你自己的浏览器**里打开 Mod 页面（`xivmodarchive.com/modid/…`）
2. 右下角面板选好 **分类 / 类型** → 点 **「⬇ 下载并导入管理器」**
3. 浏览器开始下载 → 管理器自动接住并入库 → 想装进游戏就点「安装到游戏」

### 路线 B：书签小工具
1. 管理器「下载工作台」里把那个书签拖到书签栏
2. 在 Mod 页面点一下书签 → 信息（名称/作者/封面/直链）送到管理器
3. 回工作台点 **「⬇ 用我自己的浏览器下载 → 自动入库」**

> NSFW 的 Mod 只有**你已登录的浏览器**看得到下载链接 —— 所以这两条路都刻意"用你自己的浏览器"，
> 不需要在别的地方再登录一次（内置浏览器只是可选的备用方式）。

### 检查更新 / 更新 Mod

- 表格里新增 **「更新时间」** 列：这份是从站点哪个版本下的；站点有新文件时会标 **「有新版」**
- 工具栏 **「检查更新」** → 有新版就会告诉你（勾选了 Mod 就只查这些）；
  **只检查 XMA 和 heliosphere 两个来源**，其它来源（或没填站点地址的）直接跳过，结果里会写明「跳过 N 条」；
  同时**以站点为准刷新「标签」和「影响/替换」**（手改过的会被覆盖，页面读不到时不动）
- **「更新选中」** / 详情里的 **「从站点更新」** → 从站点下载最新文件覆盖
  （旧文件进回收站，地址/编号/预览图/标签/影响替换 都保留）
- **「上传新文件替换…」**：手动选一个新文件替换（作者私下给的文件、自己改的版本都行）
- 公开 Mod 直接下载；NSFW 那种会借内置浏览器的登录态，没登录过就提示你登一次
- **再下一次同一个 Mod 会自动认成「更新」**：同一个站点地址已在库里就覆盖那条，不新建重复条目
  （浏览器拓展下载 NSFW 的更新就走这条路）
- 支持 **XIVModArchive** 和 **heliosphere.app**；heliosphere 的下载按钮拿不到直链 →
  用「打开页面下载」在你的浏览器里下好，再「上传新文件替换」

### 筛选与排序

点工具条 **「高级搜索」** 进入弹窗表单：名称／作者／影响替换／标签（下拉列出库里所有标签+条数）／
分类／安装状态／标签有无／预览图 ＋排序（默认／名称／作者／序号／更新时间／分类，可升可降）。
表格里不再有「标签」「影响/替换」列 —— 这两项在右侧详情里按项分开显示，筛选走高级搜索。
顶部搜索框是所有字段一起找，不需要再选范围。

### 详情面板与设置页

右侧详情面板从上到下是：**操作**（从站点更新／安装到游戏／上传替换／补封面 ＋ 打开文件夹 · 复制路径 · 查看原图）
→ 预览图 → 信息。主动作两列等宽对齐，文件类收成小字按钮，占面板高度约 19%。

**云存储（夸克网盘）**：Mod 载荷可归档到夸克，本地只留元数据 + 预览图 + 地址.txt
（归档 → 逐文件校验通过才删本地载荷，进回收站可还原；云端已有走秒传）。
归档后仍能「检查更新」（归档时会记下载荷时间当基线）；装进游戏时若本地没载荷会**自动从云端取回**。
归档后在**列表的名称列 / 图片墙的标题 / 详情标题**都能看到蓝色「☁」标记（停上去显示文件数、大小、云端路径）；
归档前会先查云端同名文件（有就不再传，不会重复占空间）；详情「文件」页签列本地 + 云端载荷，
点云端文件名就在管理器里下载（带进度条、可取消、支持另存为），
「在网盘里打开」会精准跳到该 Mod 的云端目录。
注意：载荷归档后「打包备份」只含元数据 + 图，恢复后需用「从云盘取回」补载荷。

备份页可在线管理：顶部概览看份数与占用，列表可按类型/文件名筛，单条能恢复 / 定位 / 删除，
也能勾选批量删、或按「只保留最近 N 份」一键清理旧备份 —— 删除默认进回收站，可还原。
**与网盘对账**：以云端实况为准重建归档状态（列表工具栏「与网盘对账」）。换电脑后如果
列表没有「☁」、详情显示「0 个文件」，点它跑一次（先「只看不改」预览）就能把云端路径、大小、
载荷清单和「已归档」状态全写回来 —— 只改索引库记录，不下载不删除文件。
设置 → 云存储 里填 Cookie 并「测试连接」即可启用（走夸克 PC 端非官方接口，改版可能失效）。

**详情三档宽度**：操作卡右上角切「窄栏 / 半屏 / 全屏」，或双击列表任意一行直接进半屏；Esc 逐级退回。
**布局照 XMA 的 mod 页分五个区**，两列宽度比 5:2（描述 / 文件 / 历史只在展开时显示）——
左列：① 标题（名称 + 版本 + 分类说明 + 站点链接）② 大图轮播（‹ › + 计数 + 缩略图条）
③ 描述区（页签：描述 / 文件 / 历史）；
右列：④ 操作（作者 → 从站点更新 / 安装到游戏 / 上传替换 / 补封面 → 图片数·载荷大小·站点版本）
⑤ 元信息（分类·更新时间·发布日期·类型·影响替换·种族·性别·标签·地址）。
「种族 / 性别 / 发布日期」来自站点，检查更新时自动带过来；「描述」是本地字段。
「标签」「影响/替换」长取值自动换行，不会被裁掉。

设置页按功能分成 5 张卡片（插件／封面同步／目录／内置浏览器／Excel），保存按钮吸在底部。

### 「影响/替换」是干什么的

Mod 装进游戏是**替换原模型**的（衣服替换某件装备、皮肤替换身体贴图…），装之前看一眼就知道会不会互相打架。

- **自动填**：下载入库时会读站点页面上的 `Affects / Replaces` 一栏（拓展面板会带出来、工作台解析链接也会带）
- **手动改**：列表右侧详情面板改完点空白处即存；「编辑」窗口里也能改；批量条里勾上「影响/替换」可一次改多条
- **能筛**：高级搜索里多选、或直接点表格里这一列的值
- Excel 汇总表里每个分类多一列「影响/替换」；重扫描不会冲掉手填的值

## 三、常见问题

| 现象 | 处理 |
|---|---|
| 管理器打不开 / 页面白屏 | 先跑 `启动Web版.bat`；端口被占会自动换端口，看 bat 窗口里打印的地址 |
| 拓展面板显示「连接不到管理器」 | 管理器没启动；或端口不是 8765 → 点扩展图标填端口 → 「连接」 |
| 拓展面板「没找到下载链接」 | 在这个浏览器里登录 XIVModArchive 后刷新页面（NSFW 必须登录才可见） |
| 点了下载，管理器没入库 | 确认浏览器下载目录和管理器「下载目录」一致（管理器会自动读你浏览器设置的下载目录，通常已经一致） |
| 游戏里点安装没反应 | 插件没启用 / 没重启游戏 / 管理器里「设置 → 游戏插件 → 自动配对」+「测试连接」 |
| 预览图不显示 | 装完后在管理器点「补封面到游戏」；Penumbra 侧预览由插件绘制 |
| **明明没装，却显示「已安装」**（第二版收死：只要"前置名"像也算的漏洞） | 规则最终是：**一边的 token 必须被另一边全包含，且多出的那一边必须是"装饰过的名字"（带数字/含作者名）**才算同一条。`Botanica` vs `Botanica Bodychain`（作者 Pocky）→ 长边没装饰 ⇒ 只认词全等 ⇒ 不算已安装。日志里会写清楚每次判定：「已安装判定：「X」↔ 已装目录「Y」→ 算已安装 / 跳过「Y」——只是名字像」 |
| **明明没装**（第一版）（如 Botanica Bodychain 被 Botanica Ruffle 带累） | 以前只按"名字子串"判断已安装 → 只要共用一个词（都叫 Botanica）就误判。现在加了 **token 复核**：短名的每个词都必须出现在对方名字里才算同一条；只共用词则不匹配，并在日志写一行「已安装判定：跳过「X」——它和「Y」只是名字像」。顺带修了短名（如 `Muse`）一直匹配不上的老 bug |
| **装 Mod 报 `[WinError 123] 文件名、目录名或卷标语法不正确`**（XMA 标题里带 `\|` 这种） | XMA 标题常带 `\|`、`:` 等 Windows 不允许的字符，以前直接拿来做文件夹名 → 必然失败。现在**建名字时自动替换成 `_`**（并写一行日志"名字里有 Windows 不允许的字符，已自动替换：…"），分类/子分类名也一样。重试一次即可 |
| **全自动，不用手动点** | 装好 2.23.5 后都是自动的：① **推送/安装前**自动把封面插进包（连插件都不用更新，图跟着包进游戏）② **归档前**自动插（云端那份从此带图，换机/取回天然带图）③ **启动后**自动体检一遍，游戏里没图的直接补进去（每天最多一次，设置里 `auto_cover_fix` 可关）。日志在 `mod_manager.log`，搜「自动插封面 / 自动封面体检」 |
| **为什么有的 mod 有图、有的没有**（如 Trigun 有、Girly Pop 没有） | 看它的**包**：Heliosphere 的包（包根有 `heliosphere.json` + `cover.jpg`/`cover.webp`）**自带封面**，Penumbra 解包时就把图带进目录 → 天然有图。普通包很多**一张图都没有**（实测 29 条里 28 条如此）→ **必须靠插件把图塞进去/写进去**，插件那一步没跑到就没图。诊断封面/封面体检里现在会直接显示「包内自带封面」这一行 |
| **重装了还是没有图** | 两种原因都修了：① 插件等不到"新目录"会直接超时退出（同名 mod 覆盖安装时就是这样）→ 0.2.13 改成**按目录名/包内 Name 找回已存在的目录继续写**；② 装完那一步本来就不可靠 → 0.2.12 起改为**把封面塞进包**（Penumbra 解包时带上）。请在 Dalamud 更新插件并重启游戏 |
| **一次把缺图的全补上** | Mod 列表工具栏点「**封面体检**」：逐条看游戏里那条目录有没有图（伪 WebP 也能认出来），结果里直接点「给缺图的补上」→ 写进已存在的目录，**不需要重装**。对不上目录的用「选目录补封面」挑一次（会记住） |
| **Penumbra 里那条 mod 一张图都没有**（连 `images\` 文件夹都没有） | 根因：Penumbra 的 `InstallMod` 只接受**包文件**、由它自己解包成目录 —— 包内没图，解出来就没图；插件以前是「装完再往目录里写」，那一步不可靠。**插件 ≥ v0.2.12** 改成「**把封面塞进包再交给 Penumbra**」，解包时自然带上。请在 Dalamud 更新插件并**重启游戏**，然后重装/补封面 |
| 换了电脑 / 重装后 mod 没有预览图 | 现在会**自动修**：点「补封面到游戏」或「诊断封面」时，管理器发现库里没图就去云端目录把图取回来。想让全部一次到位：勾选全部 →「归档到云盘」（把图一起传上去并记账）或「与网盘对账」（把云端已有的图认回来） |
| 归档后本地 mod 文件夹里没有图 | 归档会把「只存在于分类目录的同级大图」**复制一份进 mod 文件夹**（外面那张保留），mod 文件夹从此自包含 |

## 四、版本

- 管理器 ModManager **v2.23.9**（构建时间看侧栏页脚 `v2.23.9 · HH:MM`）
- 游戏插件 ModBridge **v0.2.13**（封面塞进包需要 ≥ v0.2.12）（管理器要求插件 ≥ v0.2.6，版本旧了会明确拦住并提示）
- 浏览器拓展 **v1.0.0**

三样东西都只跟本机 `127.0.0.1` 通信，不上传任何数据。
