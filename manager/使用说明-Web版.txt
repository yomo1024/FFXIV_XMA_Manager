FFXIV Mod 管理工具 · Web 版  使用说明
=====================================================================

【它是什么】
  同一个工具的网页版：后台是一个只监听本机的小服务，界面在浏览器里。
  优点：点列表换预览不再卡（服务端把 19MB 的大图转成几十 KB 的缓存 JPEG）、
        长任务有实时进度条且随时可取消、表格/筛选/图片墙比原来的窗口好用、
        可以一键切暗色；数据和原来完全共用一份（Mod 目录 + 汇总表 Excel）。

【怎么启动 / 怎么关】
  启动：双击  启动Web版.bat      （如果目录里有 ModManagerWeb.exe，它会优先用那个）
        或者直接双击  ModManagerWeb.exe
        浏览器会自动打开  http://127.0.0.1:8765

  关闭：网页右上角点「退出服务」
        或者双击  停止Web版.bat
        服务只监听 127.0.0.1，外面访问不到，关掉就不占用端口。

  命令行（可选）：
        ModManagerWeb.exe --no-browser        只起服务，不自动开浏览器
        ModManagerWeb.exe --port 8800         换端口
        ModManagerWeb.exe --root "D:\Mod库"   临时用别的 Mod 根目录（不写回配置，测试用）

【第一次用】
  打开时会弹「首次使用」：填你的 Mod 根目录（就是里面装着 衣服 / 饰品 / 武器 / 皮肤
  这些分类文件夹的那一层），点「保存并扫描」，它会扫一遍并生成 Excel。
  浏览器拿不到系统的文件夹选择框，所以这里是粘路径。

【界面一览】（顶部导航）
  · Mod 列表
      表格模式：行里有缩略图，列出 分类 / 子分类 / 序号 / 作者 / 类型 / 名称 / 是否安装
                点一行右边出大图预览和详情；「是否安装」那一列要设了 Penumbra 目录才有意义
      图片墙模式：缩略图铺开看，点一张就选中
      筛选：搜索框（作者/名称/路径）、分类、子分类、类型
      操作：添加 Mod… / 编辑 / 删除（进回收站）/ 补预览图
      多选：勾上几行会出现批量条，可以一次改分类 / 类型 / 子分类
      快捷键：↑↓ 换选中 ／ Enter 编辑 ／ Delete 删除 ／ Ctrl+F 搜索 ／ Esc 清空搜索
  · 检查 / 工具
      查重：同一个 Mod 地址、或同作者同名的，列出来可以一键「只留第一个」
      安装检查：填 Penumbra 的 Mods 目录，列出未安装的（列表里那列也会跟着变色）
      检查报告：缺地址 / 缺预览图 / 序号重复
      自动分配序号：先「预览要改哪些」，确认再执行（真的重命名文件夹）
  · 分类管理   新建/改名/删除分类、上下调显示顺序、新建子分类目录
  · 备份 / 恢复 打包备份（Mod 文件夹 + 索引库 + 汇总表 → 一个 zip，有进度、可取消）
               恢复：先看备份里有什么，再选 跳过 / 覆盖（旧的进回收站）/ 另存一份
  · 下载工作台 内置浏览器（独立配置的窗口，用来绕 Cloudflare）
               读取当前页面 → 抓封面存成某条 Mod 的预览图 / 用这个地址去添加 Mod
               从当前页面下载（下到暂存目录）；或者「监视下载目录」把下完的文件自动搬过去
               待导入列表在这里也能直接勾选导入
  · 待导入     下载目录 / 暂存目录里的 Mod 文件，选好分类一键导入（自动编号、写 地址.txt）
  · 设置       Mod 根目录 / 汇总表 / 下载目录 / 暂存目录 / Penumbra 目录 / 备份目录 /
               内置浏览器 / Excel 缩略图宽 / 是否内嵌预览图 / 表头筛选

【目录和文件】
  ModManagerWeb.exe     打包好的程序（双击即用，不需要装 Python）
  启动Web版.bat          启动器（优先用 exe；没有 exe 时用系统的 Python 跑源码）
  停止Web版.bat          把服务关掉
  mod_manager_web.py    网页版后端源码
  mod_manager.py        业务逻辑源码（和 tkinter 版共用同一份）
app_version.py        版本号唯一来源（管理器/部署包/界面都读它，改版本只改这里）
  web/                  前端构建产物（exe 里已经内置一份）
  web-src/              前端源码（Vite + Vue 3 + Naive UI），改完跑 build_web_exe.bat 重新打包
  mod_manager.json      配置（Mod 根目录、Excel 路径…）
  mod_manager.db        索引库（删掉会自动重建，扫描一次就回来了）
  backup/               备份目录（含每次生成 Excel 前的自动备份）
  .thumb_cache/         缩略图缓存（可删，会自动重建）
  mod_manager.log       运行日志（出问题先看它）

【常见问题】
  · 浏览器显示「无法访问此网站 / 拒绝连接」
      服务没起来。双击 启动Web版.bat 重来；如果提示 Python 相关错误，
      说明既没有 ModManagerWeb.exe 也没有 Python，装一个 Python 3.10+ 并勾 Add to PATH。
  · 端口 8765 被占用
      会自动往后找 8766~8776；也可以看窗口提示的地址。想固定就关掉占用的程序。
  · 网页能开但列表是空的
      点右上角「重新扫描」；还不行就去 设置 里看 Mod 根目录对不对。
  · 下载工作台读不到页面
      先点「打开内置浏览器」，在它弹出的窗口里打开 Mod 页面；如果页面上还有
      Cloudflare 的人机验证，在那个窗口里点一下验证框，过几秒再点「读取当前页面」。
  · Excel 生成失败
      多半是 Excel/WPS 正开着那个文件，关掉再生成。
  · 换电脑 / 重装
      整个文件夹拷过去 + Mod 目录拷过去 → 首次运行重新选一次 Mod 根目录；
      想还原历史就直接用「备份 / 恢复」。

【和原来的 tkinter 版的关系】
  两个版本共用同一份 Mod 目录、索引库和汇总表，随便用哪个都行，互不冲突。
  ModManager.exe 是原来的窗口版（保留着当备用）。

==================== 检查更新 / 更新 Mod ====================

【为什么要它】
Mod 站上的作者会更新文件（修 bug、加变体），但你库里那份还是旧的。
管理器会把「站点上的最后更新时间」记下来，跟本地比一比，就知道有没有新版。

【怎么看有没有新版】
- 表格里新增「更新时间」列：显示这份是从站点哪个版本下载的；
  有新版时前面会出现橙色的「有新版」小标（点它可以只看这些）
- 工具栏「检查更新」：检查全部（勾选了就只查勾选的）→ 完事会告诉你几条有新版
- 右侧详情面板也会显示「更新时间 / 站点最新（含版本号）」
- **检查更新会顺手刷新「标签」和「影响/替换」**：值以站点页面为准（本地手改过的会被覆盖），
  只有页面确实读到了这两块才写；只从版本接口拿到时间时不会动它们（免得把本地值清空）

【怎么更新】
- 工具栏「更新选中」：先勾上有新版的 Mod → 点它（会先弹窗确认，列清楚要更新哪几条）
- 或右侧详情的「从站点更新」：只更新当前这条
- 替换方式（工具栏那个下拉框）：
  · 只替换同名文件（推荐）—— 多功能变体的文件夹不受影响
  · 清掉旧文件再放新的 —— 文件夹里除 地址.txt/预览图 之外的旧文件全换掉

【不会丢东西】
更新时保留下：文件夹名（编号/作者/名称）、地址.txt、**预览图**；
标签与影响/替换会**按站点最新值刷新**（同上面那条规则）；
被换下来的旧文件**移入回收站**，弄错了可以直接从回收站还原。

【手动上传替换】
装了站上没有的文件（作者私下给的、自己改的）也可以用：「上传新文件替换…」→
选择文件（或填本地路径）→ 开始替换。保留的东西跟上面一样。

【再下一次同一个 Mod = 自动更新】
用浏览器拓展（或工作台解析）再次下载**同一个 Mod** 时，管理器认得出它是库里已有的那条：
直接覆盖更新那条记录（保留 地址.txt/预览图/编号/标签/影响替换），**不会再新建一条重复的**。
NSFW 的 Mod 用这条路更新最省事 —— 下载发生在你自己登录的浏览器里，管理器只负责覆盖入库。
（拓展面板上的队列会写「已覆盖更新已有版本」）

【支持哪些站点】
- XIVModArchive：读「最后更新时间」，有版本历史的还带版本号与更新说明
- heliosphere.app：读页面里的版本号 + 更新时间；
  但它的下载是页面上那个按钮（调站内接口，管理器拿不到直链）→
  点详情里的「打开页面下载」用你的浏览器下载，再用「上传新文件替换」覆盖

【说明】
- 从站点更新走的是「直接下直链」，公开 Mod 不需要登录；NSFW / 需要登录的会借内置浏览器的登录态，
  内置浏览器没登录过就会提示你去登一次
- 内置浏览器没账号时，也可以「从你自己的浏览器同步登录态」（要先关掉你自己的浏览器，Cookie 文件才读得到）
- 站点偶尔连不上/被挡：检查结果里会单列「读不到」，不影响其它条目

==================== 设置页 ====================

按功能分成 5 块（每块一张卡片）：
  ① 游戏内插件（地址/token + 自动配对/测试连接/刷新版本 + 版本监控）
  ② 封面同步到游戏（预览能同步哪些 / 开始同步）
  ③ 目录（Mod 根目录 / 汇总表 Excel / 下载 / 暂存 / Penumbra / 备份，每行都有「打开」）
  ④ 内置浏览器（浏览器程序 + 是否自动打开）
  ⑤ Excel 导出（缩略图宽 / 内嵌预览图 / 表头筛选）
底部有一条**吸底操作条**：打开日志 / 重新读取 / 保存 —— 滚多远都能直接点保存。

==================== 筛选（就几个填空，别绕） ====================

点工具条的 **「高级搜索」** 按钮进入（弹窗表单），跟 XIVModArchive 的搜索框一个思路：

    名称 [____]        作者 [____]
    影响/替换 [____]   标签 [▾ 选已有或直接输入]
    分类 [▾]           安装状态 [▾]
    标签有无 [▾]       预览图 [▾]
    排序 [▾]           方向 [▾]

- 前四个是「包含」匹配（不区分大小写），留空就是不看这个条件
- 「标签」是个下拉：**列出你库里所有标签和条数**（如 gear（15）），点一个就筛；也能直接输入
- 排序可选：默认（分类+序号）/ 名称 / 作者 / 序号 / 更新时间 / 分类，配升序或降序
- 「清空条件」一键复位；顶部搜索框是**所有字段一起找**，不用再选「关键字范围」
- 表单是**边改边生效**的：弹窗底部一直显示「当前显示 N / M 条」，点「完成」关掉即可

==================== 影响/替换（Mod 替换了游戏里的什么） ====================

【这个字段是干什么的】
- Mod 装进游戏是**替换原模型**的：衣服替换某件装备、皮肤替换身体贴图……
  「影响/替换」就是记下这条 Mod 替换的对象，装之前一眼能看出会不会互相打架。
- 值直接取自 XIVModArchive 页面上的 `Affects / Replaces` 一栏，
  例如：Eerie Tights ｜ Eastern Technogaskins, Eastern Technojacket ｜ Skin, Body

【自动填入（不用管）】
- 用浏览器拓展「加入队列」时，面板上自动带出该值（可改）→ 入库时写进索引库
- 用「下载工作台」解析链接（书签小工具 / 内置浏览器都算）→ 自动填进表单 → 入库时写入
- 页面没写这一栏就留空，不编造

【面板怎么排的】
右侧详情从上到下：**操作** → 预览图 → 信息（分类·编号·作者·类型·更新时间·地址·标签·影响替换）。
「操作」故意放最上面，点起来顺手。主动作两列等宽（不会长短参差），文件类收成一行小字按钮：

  [ 从站点更新 ]      [ 安装到游戏 ]
  [ 上传新文件替换… ] [ 补封面到游戏 ]
  打开文件夹 · 复制路径 · 查看原图

     · 「从站点更新」= 去 XMA/Heliosphere 看这条 Mod 有没有新版，有就自动下载最新文件覆盖本地
       （旧文件进回收站；地址 / 编号 / 预览图 / 标签 / 影响替换 全部保留）
     · 「上传新文件替换…」= 自己下好了一个新文件，手动选它替换（NSFW / 站点下不动的用这个）
     · 地址是 heliosphere 的（接口没公开下载），按钮会变成「打开页面下载」→ 你点完再上传

【详情三档宽度 —— 按需要放大】
操作卡右上角有三个档（也可以**双击列表里任意一行**，直接进「半屏」）：

  窄栏   右栏 400px（默认），边翻列表边看
  半屏   列表和详情各占一半 —— 图更大，影响/替换一行就放得下，还能继续翻列表
  全屏   详情铺满窗口，照 XMA mod 页的样子摆：
           第一行  标题条（大名字 + 更新时间 ／ 分类 by 作者 + [站点页面]）
           下面    左 = 大图 + 缩略图条 ／ 右 = 操作（主按钮整行）+ 元信息（单列、自己滚）

Esc 逐级退回（全屏 → 半屏 → 窄栏）。列表里选中的那条不会丢。

【长内容不会被裁】
「标签」和「影响/替换」取值很长时会自动换行、完整显示（以前会顶出右栏被切掉）。

【手工改】
- 右侧详情面板的「影响/替换」和「标签」一样：**按项分开显示**（多项就是多个小标签），
  点 ✕ 删掉某项、输入框里加新的，改完自动保存
- 「编辑」窗口里也能改（下拉里能选已有取值，也能直接输入新的）
- 选中多条时，批量条里勾上「影响/替换」再填/选值 → 「应用到选中」
  （留空 = 清空这些 Mod 的影响/替换；不勾就不会动它）
- 高级搜索里可以按它多选筛选；表格里点这一列的值也能立刻筛

【其它】
- 重扫描目录**不会**冲掉手填的值（只有你自己改才变）
- 生成 Excel 时每个分类表里都会多一列「影响/替换」
- 备份包里含索引库，这一项跟着一起备份/恢复

==================== 标签与高级搜索 ====================

【给 Mod 打标签】
- 点右侧面板里的「标签」输入框 → 输入标签名 → 回车即可（可以打多个）
- 选中多条 Mod 时，顶部批量条里也能「加标签 / 去标签」（输入框可直接输入新标签）
- 标签存在索引库里（mod_tags 表），和 Mod 文件夹绑定：
    · 重新扫描不会丢
    · 改 Mod 名称/分类/类型导致文件夹改名时，标签会跟着走
    · Mod 删掉后它的标签自动清理
- **标签和影响/替换都不占表格列**了（表格只看关键信息，清爽些）：
  两者都在右侧详情里按项分开显示（几项就是几个小标签，可增可删），按它们筛选走「高级搜索」
- 备份包里含索引库，标签一起备份/恢复

【高级搜索】
分栏在筛选条上点「高级搜索」打开（按钮上会显示当前生效的条件数量）：
  标签        多选；下面可选「任一 / 全部」；再加一个「标签有无（有标签/没有标签）」
  分类        可多选（和上面的单个分类筛选并存）
  作者 / 地址  包含匹配
  安装        已安装 / 未安装 / 未知（未知=还没设置 Penumbra 目录）
  预览图      有 / 没有
  关键字范围   决定顶部搜索框在哪些字段里找：名称/作者/地址/路径/分类/标签/影响替换
- 「全部标签」小云朵：直接点标签即可加入/移出筛选（带数量）
- 「清空全部条件」一键复位；「刷新标签列表」用于别处改过标签后同步

【预览图会带进游戏（规则：mod 文件夹里必须有名为 cover.webp 的文件）】
管理器点「安装到游戏」时，会把封面（coverPath）和转好的真 WebP（coverWebpPath）一起发给插件。
插件装完在 mod 文件夹里写这些，谁认哪份都能出图：
  1) <mod文件夹>\cover.webp              ← 游戏里这个 Penumbra（汉化增强版）认它（Heliosphere 的包也是这个名字）
  2) <mod文件夹>\cover.<png|jpg>          ← 有人按"固定名+扩展名"找
  3) <mod文件夹>\images\_MetaImage.<ext>  ← 官方版/包作者的命名习惯
  4) meta.json 的 Image 指向 3)            ← 官方版读它，并通过 IPC 给别的插件
已经有 cover.webp 就跳过（不动 Heliosphere 给的图）。
包（.pmp）里自带封面时，插件会直接从包内抽出来用——Heliosphere 的包全都自带 cover.webp。
封面图从哪来？Mod 列表里点「补预览图」抓；抓不到就手动「添加图片」。
已经装好的 mod 想补封面：设置页 →「封面同步到游戏」→ 先「预览能同步哪些」→ 再「开始同步」。
管理器点「安装到游戏」时，会把本机封面图路径（coverPath）一起发给插件。插件装完后写两份：
  1) <mod文件夹>\cover.jpg                 ← 游戏里这个 Penumbra 显示封面就靠它（固定文件名）
  2) <mod文件夹>\images\_MetaImage.<ext>   ← 官方版/包作者的习惯命名
  3) 并把 meta.json 的 Image 指向 2)         ← 官方版读它，也通过 IPC 给别的插件
如果 mod 里本来就有图（包里自带、或 Heliosphere 装的那份 cover.jpg），插件不覆盖，只跳过。
封面图从哪来？Mod 列表里点「补预览图」抓；抓不到就手动「添加图片」。
已经装好的 mod 想补封面：设置页 →「封面同步到游戏」→ 先「预览能同步哪些」→ 再「开始同步」。
